# 项目审查与修复（2026-10-16）

本轮检查了项目约定、配置与订阅生成事务、规则列表与远程规则集管理，并运行服务端工作区检查、CLI 回归、安装器测试及已有真实内核兼容性门禁。以下六类确定缺陷已修复；这份记录不代表穷尽所有潜在问题。

## 问题与修复

| 优先级 | 问题与触发方式 | 修复位置与行为 |
| --- | --- | --- |
| P1 | `rule add/remove` 和规则列表导入在生成校验前改写源文件；失败后源文件残留新值。并发操作还可能覆盖另一操作的更新，固定 `.tmp` 文件名也可能碰撞。 | `src/cli/commands/rule.rs`：操作锁覆盖读取、修改、生成及失败恢复；恢复原始字节或删除本次新建文件。列表写入复用 DeploymentStore 的原子写入机制。导入也使用同一事务。 |
| P1 | `rule-set add/remove/interval` 先保存配置再生成，校验失败留下新配置和旧订阅；读取配置到写入之间也未持有同一把锁。 | `src/cli/commands/ruleset.rs`：持锁读取配置，复用已验证的配置与产物事务；检查通过后发布，存储权限准备失败时恢复快照。 |
| P1 | 配置事务只校验服务端产物，遗漏合并后的客户端配置；常规重新生成的额外校验也未把远程规则集注册算作定制内容。 | `src/subscription/artifacts.rs`：两条路径都在发布前校验合并后的完整客户端配置，覆盖覆写、本地列表和远程规则集。 |
| P2 | CIDR 校验拒绝 `2001:db8::/32` 等合法压缩 IPv6，却接受 `garbage:address/64` 等非法地址。 | `src/rule_list.rs`：使用标准库 IpAddr 解析地址，并按 IPv4/IPv6 限制前缀长度。 |
| P2 | 带 `no-resolve` 的规则被写成 `IP-CIDR,10.0.0.0/8(no-resolve)`，下次加载即报错，导致后续规则管理失效。 | `src/rule_list.rs`：写为可再次解析的 `IP-CIDR,10.0.0.0/8,no-resolve`。 |
| P2 | 文本导入使用子串去重，已有 `api.example.com` 或注释会误阻止 `api.example` 等规则加入；导入还丢弃 `no-resolve`。 | `src/cli/commands/ruleset.rs`：对已解析规则精确比较，保留解析后的标志；重复导入保持幂等。 |
