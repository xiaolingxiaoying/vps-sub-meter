代码侧验证：Windows 和 WSL 全工作区测试、`cargo fmt --all --check`、全部目标/特性的 Clippy `-D warnings`、无默认特性的发布信任测试通过。独立固定内核测试检查完整客户端和分组配置，实际运行 Xray、sing-box 与 Mihomo 互通。

客户端配置校验使用 sing-box 1.10.7、1.11.15、1.12.25、1.13.21、1.14.1；测试 VPS 使用 sing-box 1.14.2 和 Xray 26.10.31。Mihomo 1.19.30、固定官方 1.19.33 均执行配置检查，1.19.33 的 XHTTP TLS、WS TLS、Trojan TLS 转发通过。固定归档摘要与测试命令已写入 CI。

Mihomo 的初始监听可能早于 provider 就绪；本轮测试曾出现启动瞬间关闭连接，已给临时测试客户端增加启动观察时间，并让测试源站忽略未携带完整 HTTP 请求就关闭的连接。修正后固定 1.19.33 转发连续五轮通过。VPS 凭据测试还发现 HTTP 套接字激活先于 systemd 健康状态就绪，已修正激活等待并完成凭据复测。

订阅凭据与入口地址保留。原先三个自签名 TLS 组合的分享 URI 补充 `allowInsecure`/`insecure` 选项，因此不能宣称最终所有 URI 字节相同；节点身份、地址、端口、路径和引用均已逐项比较保留。普通 Xray Reality 的未验证客户端表示会被过滤，Xray 上的 VMess 显式输出 AEAD，详见[使用说明](managed-deployment.md)。

## 发布前剩余门禁

1. 在可用 Docker/systemd 环境执行完整 Debian 12、Ubuntu 22.04/24.04 矩阵；本轮宿主与 VPS 均未启用 Docker，不能把已加入 CI 的脚本当作已执行结果。
2. 在实际 GUI 客户端导入，记录 App 名称与版本；当前结果来自对应命令行内核。
3. 正式版本签名、升级/回退发布流水线与稳定分支合并。测试 VPS 上运行的是开发候选。

新装仍使用既有 sing-box 安装流程，随后迁移节点仓库、安装目标内核并选择模式；尚未把初始安装向导改为直接引导 Xray 单内核。

## 后续修正：私有 IP 规则集 404

用户反馈 1.14.4 客户端在路由初始化时无法下载 `geoip-private`。VPS 确认 SagerNet 对应 SRS URL 返回 404；这是客户端模板问题，此前的 `check` 测试没有启动远程规则集下载，不能覆盖该故障。

修正标准/精简模板为内置 `ip_is_private` 直连并移除该远程条目，保留其他分流与规则顺序。官方 sing-box 1.14.4（发行归档摘要校验通过）在空缓存下实际初始化路由成功；测试移除 TUN/监听器和控制器，只验证远程规则集加载。此测试已加入 CI。VPS 原订阅地址重新发布，保留的三个 SRS 均下载成功，两个代理进程无需重启。结果见[修正验证](../.scratch/unified-management/private-rule-fix-verification.json)。
