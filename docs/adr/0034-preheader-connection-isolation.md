# 在请求头和 TLS 握手之前隔离连接资源

## 问题

请求级 IP 限流在收到 HTTP 请求头后才执行。同一来源可在 5 秒请求头期限或 10 秒 TLS 握手期限内占满全局 32 个连接槽位，此时另一来源也会被立即断开。定时清理能回收连接，却不能在攻击持续时维持其他来源的可用性。

## 决策

直连 HTTP、Direct HTTPS 与 ACME 在接受连接后、开始读请求头或握手之前，同时申请全局与来源额度：每个监听器最多 32 个活动连接，同一来源最多 8 个。额度由连接任务持有，完成、失败、超时、取消都自动释放。IPv4 与对应 IPv4 映射 IPv6 地址共用来源额度；来源表仅保存活动连接，大小不超过全局连接数。

ExternalProxy 保留全局限制，跳过后端按来源的限制，因为真实来源在后端均表现为前置代理。仍不信任客户端可伪造的转发头；代理负责其来源限流。ACME 不进行请求频率限流，活动连接额度不限制验证器先后进行的验证请求。

## 限制

共享公网 IP 的客户端共享 8 个并发额度，正常顺序刷新不受影响。此措施处理单来源连接占用；多个来源仍可能占满全局额度，不能替代前置网络防护或抵挡链路带宽耗尽。
