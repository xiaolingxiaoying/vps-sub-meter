# 托管文件变更固定到目录句柄

## 问题和决策

初始化工件、锁文件及证书生成原先使用路径创建或替换文件。即使最终文件使用 O_NOFOLLOW，祖先目录仍可能是符号链接；目录预检查与后续创建、提交、清理之间也存在竞态。临时树实验确认旧版 root 写入会越过部署目录，修改普通 UID 无权访问的 root-only 哨兵文件。

Unix 生产路径由 `managed_fs` 逐级通过 O_DIRECTORY/O_NOFOLLOW 打开目录，必要时相对当前句柄 mkdirat。临时文件创建、renameat 提交、失败清理和 unlinkat 删除都只使用固定目录句柄及单一文件名。目录随后被改名、原路径变成链接时，操作仍作用于已打开的原目录，不转到链接指向的其他目录。

此方案依据 [openat 的目录句柄语义](https://man7.org/linux/man-pages/man2/open.2.html)、[renameat](https://man7.org/linux/man-pages/man2/rename.2.html) 和 [unlinkat](https://man7.org/linux/man-pages/man2/unlink.2.html)。它固定的是目录对象；不声称阻止有权限的账号移动该目录，也不把 `--root` 适配器当作 chroot。

## 写入、权限和清理

- 新目录 0700、新临时文件 0600；不重置现有目录的属主或模式，保留 root:sbctl 1771 等部署权限。
- 常规托管文件和 root-only 备份的属主、模式直接作用于暂存文件句柄，在同步及原子提交前完成。策略失败保留旧目标，清理尚未提交的暂存文件。
- 打开既有锁文件不带 O_CREAT；不存在时独占创建，保持 protected_regular 系统配置下的兼容性。
- 工件文件名拒绝根、父目录、分隔符和 NUL，错误返回而非 panic。
- 最终目标是叶子链接时，原子替换只替换链接本身，不修改其指向的内容；证书复用则拒绝叶子链接。证书文件同样经公共原子写入，权限在提交前就绪。证书固定只处理目录和已知密钥/证书文件，不再递归 chgrp 任意内容。
- 回滚及旧工件清理通过无链接父目录解析后 unlinkat，不删除重定向目录中的同名文件。

## 平台和验证

Debian/Ubuntu 生产保证来自 Unix 目录句柄实现。Windows 开发适配保留路径变更，增加父目录 reparse/link 检查；未声称具备同等竞态防护。

测试覆盖链接祖先、叶子目标、锁、提交与清理期间目录替换、权限策略失败、保留现有目录权限、证书私钥链接，以及过期工件清理。真实 UID 的临时树脚本确认普通账号无法访问目标，仅旧版 root 写入会修改目标，新版拒绝；不修改系统目录或实际部署。
