# 证书对按目录代际发布

certificate::pin 原先分别提交证书和密钥。隔离 CLI 的 RLIMIT_FSIZE 实验确认第二个较大的私钥写入失败后，新证书和旧私钥会留在磁盘，服务重启无法加载。

Linux 生产实现先在固定父目录下创建私有暂存目录，完整写入、设置权限、同步新文件与目录；通过 renameat2(RENAME_EXCHANGE) 一次交换已有主机目录，首次发布也交换预先建立的空目录。提交前失败保留旧目录，不依赖再次写入磁盘来回滚。目录交换的原子语义来自 [Linux rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html)。

保持原有固定证书路径。旧主机目录的其他常规文件通过相对句柄硬链接保留，保留内容、属主、权限、mtime 和 inode（链接操作会改变 ctime）；不递归复制、不跟随链接，遇到目录、链接或特殊内容时明确拒绝更新并保留旧目录。托管证书目录是平面存储，未知的常规辅助文件与另一对自签名文件可继续保留。单个 PEM 读写上限 1 MiB、目录最多 1024 个条目。父目录内独立锁协调证书发布，不重入部署 operation lock。

暂存及旧目录清理仅相对已打开的目录句柄删除叶子文件并移除空目录；提交后清理或目录同步失败不谎报旧代仍生效。异常退出前的暂存目录可能留在磁盘，权限仍私有或仅证书共享组可读，不将其当作活动目录。

发布锁保持 root 拥有、0600。自签名存储的通用 0640 PEM 授权排除此锁，更新恢复的文件策略也单独处理；服务账号能读取证书不代表可以打开并 flock 特权发布锁。

## sing-box watcher 与特权刷新

v0.0.20 候选在 VPS 隔离命名空间中暴露兼容性故障：目录交换后，真实 sing-box 1.14.2 仍提供旧证书。[该版本 TLS 源码](https://github.com/SagerNet/sing-box/blob/v1.14.2/common/tls/std_server.go) 使用 [fswatch v0.1.2](https://github.com/SagerNet/fswatch/blob/v0.1.2/watcher.go) 监听 PEM 的父目录，目录被替换时不重新注册。此候选未发布，修复后以 v0.0.21 验收。

Linux 对内容和目标属主/权限均未变化的 pin 保留原目录。真正发布新代后，特权证书 CLI 仅对拥有正确部署标记和本工具单元标记的数据平面执行 try-restart，不重启订阅服务，也不启动管理员已经停止的服务；安装和模式事务仍通过自身服务提交路径刷新。一次新代刷新会短暂中断现有代理连接。失败明确报告“已发布但刷新失败”，不能暗示证书文件已回滚。

新代内同时提交 root-only 的 .sbctl-refresh-pending 标记。即使进程在发布后退出或 try-restart 失败，后续相同证书的 CLI 重试也会完成未确认的刷新；成功后安全删除标记。无变化且已确认的 pin 不交换目录、不重启核心。该内部文件名保留给发布协议，另一对自签名文件与常规辅助文件仍保留。

订阅服务固定打开主机目录后打开两份 PEM，再读取内容，避免混合代；若旧代在第二个打开前被清理，只产生暂时的读取失败，后续读取新代，既有内存证书仍可服务。TLS stamp 增加目录设备/inode，避免相同 mtime 漏掉一次交换，保留前后检查和内存中旧证书回退。非 Linux 开发适配使用暂存后目录重命名和恢复，不声称具备 Linux 原子交换或 Unix 句柄竞态保证；生产平台仍为 Debian/Ubuntu。
