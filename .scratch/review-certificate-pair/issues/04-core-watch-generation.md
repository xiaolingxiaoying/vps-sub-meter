# 目录交换使 sing-box 原目录 watcher 失效
Status: resolved

v0.0.20 候选未发布。核对实际固定的 sing-box 1.14.2 源码后发现，其 fswatch v0.1.2 监听 PEM 的父目录，目录 Rename/Remove 后不重新注册。整目录交换可能令后续证书无法自动加载。需用真实内核和两代临时证书握手复现；证书 CLI 在成功发布新代后，对本工具拥有的现有数据平面执行 try-restart，并显式报告刷新失败。无变化的证书不交换目录，避免无意义的断连；状态查询、未安装或第三方单元不得触发重启。

## Answer

VPS 私有网络命名空间中用 v0.0.20 Actions 程序和真实 1.14.2 核心确认旧证书继续被提供，候选未发布。v0.0.21 新代发布后仅对有正确部署/单元标记的数据平面 try-restart；未变化的已确认 pin 保留目录及进程。刷新标记随新代提交，顺序失败重试不会因证书未变而遗漏刷新。真实核心 1.14.1/1.14.2 的握手、刷新失败及恢复均通过，新增门禁已进入 CI。两个特权命令并发确认的时序单独留在 [05](05-refresh-ack-concurrency.md)，不将此项顺序测试当作并发问题已解决。详见 [验收记录](../verification.md)。
