# 证书与私钥作为同一代发布

审查续期或 pin 写入失败时是否保留可用的成对证书。仅在临时目录和 CLI 子进程故障注入中研究；不得破坏实际证书。

## 设计约束（下一轮待评估）

- 先完整暂存并校验两份内容及权限，失败时旧代文件保持完整；仅把单文件恢复作为补救不能保证 ENOSPC 等二次失败下仍可用。
- 评估 Linux 同一父目录内目录交换等成对发布方案；生产仅支持 Debian/Ubuntu，但开发平台仍需可编译、明确降级边界。
- 服务端 sing-box 使用固定证书路径；同一主机目录可能已有自签名 cert.pem/key.pem 与固定 fullchain.pem/privkey.pem，不能因切换一对而静默删除另一对或未知管理员内容。
- 现有无链接父目录规则、固定目录句柄、共享组 0750/0640、目录替换时的竞态和失败清理都要保留；不通过新增可重定向链接绕过边界。
- TLS 读取可能跨越提交时刻，需确认现有 stamp 前后检查与旧内存证书回退仍正确，并覆盖更新后实际重启可用性。
